# Hisab 0.2.0 private source checkpoint

11 November 2026. Work in progress, NOT a release. The visible app is still local-only. Do not describe it as working Google sign-in/sync.

## Current UI
- Amount-first entry: Expense, Income, Lent, Borrowed and Transfer; searchable category choices.
- 28 seeded categories plus custom categories/accounts/people. Names, original icon and six non-orange colour choices are locally editable; renames preserve debt links, transfer endpoints, balances and budget categories. Unused categories/accounts/people can be removed with confirmation; quick-entry defaults reset. Referenced items cannot be removed, preventing broken history. Archiving referenced items is not implemented.
- Larger original glyphs: 36dp entry/list tiles, 44dp scrollable icon grid/editor previews; category sheet redrawn at larger scale. Account/person colours/icons now shown in overview/activity/People. No imported stock assets.
- Local display settings: dynamic or five manual palettes, show/reorder home sections, four date formats, symbol/code currency display and Indian/international/no grouping, quick-entry type/account/category defaults keyed by entity ID. Language and light/dark settings join validated backups.
- Single-currency ledger supports ten two-decimal currencies for an empty ledger. Currency cannot be silently relabelled or converted once entries/budgets/goals exist. No mixed-currency or FX conversion feature.
- Budget tap-to-edit amount/category keeps its UUID. Goals edit in place and have explicit removal confirmation. Backups migrate older budget/goal IDs safely and restore catalogs/preferences atomically.
- More/settings redesigned with grouped large-icon rows, clear secondary labels, local-only privacy card, appearance/customization near the top, backup section and separate About. Light English, dark Malayalam and scrolled bottom rendered and inspected. Dedicated original settings glyphs added; category icon picker still has the original 28 choices.
- No fixed orange UI. Android 12+ wallpaper-derived system color tokens, teal fallback before Android 12 and if the selected dynamic accent is orange. Light/dark English/Malayalam framework renders inspected.
- Material 3 library1.14.0 theme and MaterialButton controls are integrated; DynamicColors applies to the Activity. Other list/form surfaces are custom native views. No liquid glass effect or claim.
- Orange H launcher remains default. Teal, Blue, Violet, Rose and Graphite adaptive-icon variants selected through activity aliases. Framework alias state tests pass; live launcher behavior unverified.
- Full local debts/partial repayments, linked repayment edits/deletes, principal validation, schema-2 backup validation and CSV debt fields.

## Cloud integration: implemented but gated off
The actual private preview remains local-only. CloudConfig.ACCOUNT_UI_ENABLED is false and the merged APK has no INTERNET permission. No Google/Drive workflow has run on a real device.

- GoogleConnection uses Credential Manager plus a separate Drive permission request, then verifies the access token's subject and verified email with Google's HTTPS userinfo endpoint. It does not parse/trust an ID token or use an AiCoN backend.
- VerifiedDriveAccess holds only a memory token, bound to one subject and a conservative expiry. AccountDirectory stores device-private subject/email metadata, not tokens or ledger backups. Recording a verified account never selects or imports a ledger.
- LedgerController owns explicit local/known ledger selection, remembered offline caches, matching-account reconnect, memory-token disposal, worker ownership, error/review/reset statuses, last successful sync and stale callback rejection. Switching never copies records. A busy foreground operation blocks switching rather than completing under another account.
- AccountUi is attached only behind the disabled gate. English/light and Malayalam/dark account screens were framework-rendered and visually inspected with a fictitious account. Copy/reset/forget/discard choices name their account. Account changes dismiss old dialogs; destructive effects also verify the expected subject. Copying local records requires a fresh empty Drive/account check and keeps the source. Forget explicitly does not claim deletion or Google permission revocation.
- SyncModel and SyncEngine use vector clocks, a causal frontier, explicit conflicts, immutable outbox operations with reserved Drive IDs, and permanent content-free tombstones. No timestamp last-writer-wins choice.
- ConflictReviewStore retains every frontier version plus the whole candidate ledger. Each review has a fresh random key and exact local revision. Choices across multiple conflicts are staged without applying a partial ledger. Only a fully valid result and its outbox commit together. Changed local state or an old dialog key rejects a stale choice. Cross-record validation failures still stop safely without a complete repair UI.
- LedgerSyncStore captures financial/catalog/preferences edits atomically, preserves navigation row IDs on merge and rejects mixed currencies/invalid linked repayments. Open form tickets check persisted revision as well as the session generation, so another worker/session's merge cannot be overwritten by an old form.
- ResetIntentStore / ResetCoordinator persist publication/file reservations and cleanup phases, survive a lost publication response, and keep edits blocked on incomplete reset. Slow network no longer holds the UI session lock; database phases still share that lock. Reset clears retained review content. Content-free reset/deletion markers remain to stop offline resurrection; the confirmation discloses this.
- BarrierRemote / DriveBarrierTransport use reset-tagged schema3 operations. Schema2 history blocks for explicit migration, not silent overwrite. Every background HTTP request checks the selected account; session guards also recheck local reset history and pending reset state. Late old-epoch files are ignored and scrubbed on a later successful sync.
- GoogleSilentAccess is a background-only authorization path for previously granted scopes. It never launches a resolution or silently chooses another Google account. Returned identity is verified again. BackgroundSync checks selection before authorization and every effect, disposes its token and stores only coarse private status.
- HisabSyncWorker / SyncWorkScheduler compile behind the same disabled gate. Planned behavior is a coalesced edit job and one selected-ledger 30-minute periodic job, network constraints, battery protection for periodic work and bounded exponential retry. Android can delay work. The background core has fake-authorizer tests; actual WorkManager scheduling, Play Services authorization and OS process-death behavior are not verified.

2. Complete repair/review for cross-record conflicts such as independently valid repayments that exceed principal when combined, account-name uniqueness collisions and currency/settings conflicts. Current validation preserves existing data but may require manual recovery.
3. Audit restore/export/crypto callbacks and form lifecycle against ledger switching, process death and background merges. Account-ledger restore is currently blocked; restore into the separate local-only ledger instead.
4. Real WorkManager scheduling/cancellation/retry/process-death tests; foreground and background coexistence; Android lifecycle/UI refresh; expired tokens; picker cancel/wrong-account/reconnect. Background coordinator tests are not actual OS job execution.
5. Live Google/Drive checks with the registered private certificate: correct account and scopes, local-copy isolation, offline edit/deletion/reset, crashes, retries, concurrency and no resurrection. No such live test was performed here.
6. Measure Drive round trips and immutable-operation growth for larger ledgers. History/transport compaction and performance are not established by local simulation.
7. Referenced-entity archiving, remaining dialog polish, narrow screens/large font, accessibility, keyboard/system-bar overlap and real launcher refresh.
8. Update and review the unpublished privacy draft, legal identity/contact and actual behavior before any publication. Keep reset-marker retention clear. No public privacy policy URL is configured.
